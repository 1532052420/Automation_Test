# 失误复盘案例库（Retrospectives）

> 定位：不是规则集（规则固化在 self-test-gate 门禁 / AGENTS.md 条款），是**案例库**——
> 每条案例记录「现象 / 根因 / 怎么发现 / 怎么修复 / 沉淀了什么规则」，供后续任务检索同类风险。
> 追加纪律（2026-10-20 用户要求）：**每次代理失误的复盘都必须追加到本文件**，
> 并在任务收尾声明中说明「本任务失误复盘情况」。

## 追加流程

1. 失误按流程处理：先查证复现定位根因 → 再方案 → 再修复（门禁与流程见 self-test-gate / AGENTS.md）
2. 按下方模板把案例追加到「案例」节（**最新在最上**）
3. 复盘若催生新规则 → 固化进 self-test-gate / AGENTS.md（案例库记叙事，规则进门禁）
4. 收尾声明中说明「本任务失误复盘已追加至 retrospectives」或「本任务无失误」

## 案例

### 2026-10-21 · 误判浏览器下载卡死过早 kill，旧缓存目录被当成下载进度误读（验证类任务，当轮修复）
- 现象：给 trace_lab 装 Playwright 时 `playwright install chromium` 跑了 20+ 分钟未完，`du` 显示缓存目录 523MB 且两次采样体积不变，判定「下载卡死」kill 之；重启下载后报错要 revision 1248，而磁盘上是 chromium-1200——才发现 523MB 是 9 月遗留的旧版浏览器缓存，真正的 1248 下载一直在后台以 ~15KB/s 缓慢推进，被 kill 的是健康进程。
- 根因：①把「目录体积不变」直接等价于「进程卡死」，没有区分**缓存总量**与**本次下载目标目录**（新构建下载先写临时 zip，完成前主目录不动）；②kill 只杀了父进程，`oopBrowserDownload` 子进程存活继续写临时文件，造成「二次下载也很慢」的假象叠加误判；③判据采样两次就下结论，没看进程网络连接（lsof 有 ESTABLISHED 即在下载）。
- 怎么发现：重启后 playwright 启动报「Executable doesn't exist at ...chromium_headless_shell-1248」，与磁盘 1200 矛盾 → 回溯浏览器目录时间戳（Sep 17）确认缓存是旧的，因果闭环。
- 修复：改用零下载方案——查各版本 browsers.json 确认 revision 1200 ↔ playwright v1.57.0，pip 钉到 1.57.0 直接复用磁盘浏览器，录制端与 viewer 资产同版本；冒烟 + 端到端全绿。
- 沉淀：**判「进程卡死」必须先看网络连接与目标产物的时间戳，不能只看无关目录的体积**；长下载一律先确认缓存里已有构建与目标版本的 revision 匹配关系（browsers.json），匹配则钉版本复用，避免整段下载；kill 安装器后必须 `pgrep` 全链确认子进程（下载器是独立进程）已退出。

### 2026-10-21 · 版本奇偶判定与 push 串在同一命令里，单数版本误推远端（流程违规，当日如实报告）
- 现象：收尾执行 version-github-release 时，把「判定奇偶」和「add+commit+push」用 `&&` 串在一条命令里——判定输出 `6.16.25 1`（单数）后命令继续执行，推送已完成，违反「单数不上传」用户契约。
- 根因：**判定必须是独立的前置闸门**，与写操作串接后判定结果失去拦截能力；写命令时顺手合并步骤，省了一次往返却砍掉了门禁。
- 怎么发现：push 后核对 ls-remote 输出与奇偶结果时发现矛盾（6.16.25 尾号 1 = 单数，远端却有 cc21b3b）。
- 修复/补救：铁律禁止 force 回退，远端无法无痕撤除；如实向用户报告，交由用户定夺（保留/授权 force 回退/下个双数版本前滚覆盖）。提交内容本身完整无害（样式修复 + changelog）。
- 沉淀：**判定类检查永远独立成命令**，其结果人工确认后才允许执行后续写操作；凡「条件 A 成立才做 B」的流程，绝不能把 A 的判定和 B 的执行写进同一条 shell（&& 只保证顺序，不保证条件）。

### 2026-10-21 · 代码生成器三缺陷同根因：拼接/正则无锚定（单元测试首轮全拦，未流出）
- 现象：实现「步骤级等待覆盖写码」时，首轮单元测试连续抓出三个缺陷——①kwargs 拼到调用括号外（`f(), wait_seconds=8` 语法错误）；②签名正则双重转义（`sig_re` 自带 `\(self\)` 又被外层 `\(%s\)` 包裹成 `((self))` 永不匹配）；③方法体正则未锚定行尾，带行尾注释的非标准方法被误判为标准形态而放行改写。
- 根因：代码生成器的字符串拼接与正则匹配靠目测，没有先写「生成→反解往返」用例再动手；三处都是拼接点/锚点不严。
- 怎么发现：self-test-gate 行为自测的离线单测第一轮（断言 case_step_line 输出、签名匹配、非标准拒绝）逐一拦截，未到浏览器层更未落盘污染。
- 修复：kwargs 改在括号内拼接（位置参后接带前导逗号的 kwargs 串）；正则拼接改为 `def NAME` + sig_re 直接相连（sig_re 自含完整签名）；体匹配加 `[ \t]*$` MULTILINE 行尾锚定。
- 沉淀：**改代码生成器必须先写生成↔反解往返断言再动手**（往返是自校验闭环，一行不对即炸）；凡「识别是否标准生成形态」的正则必须锚定行尾（`$` MULTILINE），行尾注释/附加代码是常态；保护性校验（防覆盖手工改动）的测试必须真实构造非法样本，只测合法路径等于没测。

### 2026-10-21 · visView 包裹层插入位置错误，把两个断言蒙层包进隐藏视图致弹窗不渲染（v6.16.21 修复，自测拦截）
- 现象：修复「页签与内容分卡」时把 `#visView` 开标签插在 `#asEditMask`/`#asImgViewer` 之前——列表页签下点「编辑断言」，弹窗 `shown=true` 但蒙层 0×0 全屏不渲染（祖先 `#visView` 为 display:none）。
- 根因：Edit 移动包裹层开/闭标签时，只核对了文本行增删，没有推演**DOM 包裹关系**的变化——开标签位置比闭合标签位置提前了两个蒙层。
- 怎么发现：行为自测对弹窗加 `coversViewport`（bounding rect ≥ 视口 98%）断言，`shown=true` 与 `rect=0×0` 矛盾暴露；沿 parentChain 定位到蒙层被包进 visView。
- 修复：visView 开标签挪到 asImgViewer 之后；HTML 平衡校验增加「蒙层必须在 visView 之外」的结构断言；复验 4 个弹窗全部铺满。
- 沉淀：**文本 diff 审计 ≠ 结构审计**——移动包裹层（div 开/闭标签）的改动，必须断言关键元素的祖先链（谁的子元素、在哪个视图内），不能只看行增删；隐藏视图内的元素 `shown` 类断言会假真，弹窗类自测必须加「铺满视口」几何断言。

### 2026-10-21 · #visuals 深链兼容只改了 showRunPanel 一个入口，直开场景被 includes 检查短路（v6.16.20 开发中，浏览器实测拦截）
- 现象：视觉断言并入断言管理后，菜单点击切换正常，但 `/run#visuals` 刷新直开落在项目管理面板，兼容映射未生效。
- 根因：同一面板名有**两个入口**——菜单点击走 `showRunPanel(name)`，刷新直开走 `initRunPanels()` 里 `RUN_PANELS.includes(start)` 的白名单检查。兼容映射只加在 showRunPanel 开头，直开时 'visuals' 先被 includes 判为非法、替换成 `RUN_PANELS[0]`（项目管理），根本走不到映射分支。
- 怎么发现：self-test-gate 行为自测用浏览器实测「菜单点击 / 刷新直开」两条路径，第一轮直开即复现。
- 修复：映射提为独立函数 `normRunPanel(name)`，showRunPanel 开头与 initRunPanels 深链计算两处都先过同一映射；修复后两条路径复验通过。
- 沉淀：改「hash 深链 + 函数分发」双入口结构时，兼容/归一逻辑必须放在**白名单校验之前**并抽成函数供两个入口共用；行为自测必须覆盖「菜单点击」与「刷新直开」两条路径，只测点击必漏直开。

### 2026-10-20 · Charles 抓包用全局代理，Mac 端代理退出致真机整网瘫痪（环境配置，当日回滚）
- 现象：用户手机 WiFi 满格但完全断网，要求删除已装证书并全部恢复原样。
- 根因：为抓包用 `adb shell settings put global http_proxy 192.168.5.185:8888` 给真机设了**全局代理**——该键作用于设备全部流量且无失效保护；Charles 进程退出（用户关闭）后代理指向死端口，整机流量发往不可达代理 → 断网。且配置时把「Mac 端 Charles 退出 = 设备断网」的依赖只写在交付末尾的回滚命令里，未作醒目风险提示。
- 怎么发现：用户报「手机怎么没网络了」→ 取证闭环：pgrep 无 Charles 进程 + 设备 global http_proxy 仍指 Mac + 设备仍在 wlan0 → 因果成立。
- 修复：`settings delete global http_proxy`（dumpsys connectivity 恢复 VALIDATED）；删除已推送的证书文件，查证用户证书未装上（受信任凭据-用户页「无凭据」，无需删）；退出 Charles 并把访问控制白名单改回原状。
- 沉淀：**新规则固化进 AGENTS.md「八、真机抓包代理铁律」**——(1) 优先 WiFi 手动代理，慎用全局 http_proxy（它连蜂窝网络也指向死代理）；(2) 断网依赖必须在交付首条醒目说明；(3) 抓包收工立即清理设备代理/证书并还原代理端配置，除非用户要求保留。

### 2026-10-20（持续性）· BSD grep BRE `\|` 交替反复踩坑（当日 8+ 次）
- 现象：`grep "a\|b"` 静默返回 0 结果，连续误判「函数不存在 / 内容缺失 / 接口无定义」。
- 根因：macOS 自带 BSD grep 的 BRE 不支持 `\|` 交替；肌肉记忆反复覆盖已知教训（当日记录三次仍复发，含一次据此差点得出错误排查结论）。
- 怎么发现：查询结果为 0 与已知事实矛盾时，回头复查工具本身。
- 修复：所有受影响查询用 `grep -E` 重跑纠正结论。
- 沉淀：**硬规则升级——本项目一切多模式 grep 必须写 `-E`，禁止 `\|`**（从 memory 备忘升级为本 skill 案例级纪律）。
