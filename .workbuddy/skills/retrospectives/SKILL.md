# 失误复盘案例库（Retrospectives）

> 定位：不是规则集（规则固化在 self-test-gate 门禁 / AGENTS.md 条款），是**案例库**——
> 每条案例记录「现象 / 根因 / 怎么发现 / 怎么修复 / 沉淀了什么规则」，供后续任务检索同类风险。
> 追加纪律（2026-10-20 用户要求）：**每次代理失误的复盘都必须追加到本文件**，
> 并在任务收尾声明中说明「本任务失误复盘情况」。

## 追加流程

1. 失误按流程处理：先查证复现定位根因 → 再方案 → 再修复（门禁与流程见 self-test-gate / AGENTS.md）
2. 按下方模板把案例追加到「案例」节（**最新在最上**）
3. 复盘若催生新规则 → 固化进 self-test-gate / AGENTS.md（案例库记叙事，规则进门禁）
4. 收尾声明中说明「本任务失误复盘已追加至 retrospectives」或「本任务无失误」

## 案例模板

```
### YYYY-MM-DD · 一句话标题（v版本引入，v版本修复）

- 沉淀规则（指向 self-test-gate 门禁 / AGENTS.md 条款 / 跨项目备忘）：
```

## 案例

### 2026-10-20 · loadElements() 初始调用被 Edit 替换误删（v6.16.07 引入，v6.16.08 修复）
- 现象：进入元素管理，元素文件列表 0 行、空态提示也未出现。
- 根因：Edit 是精确替换不是插入——old_string 选了含 `loadElements();` 的整段，new_string 末尾错写成 `loadPageFiles();`，该行在替换文本中丢失；node --check 通过（语法合法但调用缺失是语义问题，语法检查天生查不出）。
- 怎么发现：用户进面板报「没有显示数据」；grep 实锤 initElementsPanel 尾部只剩 loadPageFiles()；浏览器复现 0 行 → 手动 await loadElements() 后 2 行，根因闭环。
- 修复：恢复 loadElements() 与 loadPageFiles() 并列初始调用，附防再犯注释（v6.16.08）。
- 沉淀：self-test-gate 门禁二「改动行审计」（diff 每行删除行逐一确认有意；old_string 含既有行时 new_string 必须带回）+ 门禁三「影响面回归」（新功能全绿 ≠ 旧功能健在）。

### 2026-10-20 · 未经授权添加网页 30s 轮询守护（v6.16.05 引入后整体 revert）
- 现象：用户要求「重启服务成功后的刷新改成强刷」，会话理解成网页自动刷新，向页面添加 30s 轮询 + 更新横幅。
- 根因：需求词「刷新页面」的载体判断错误（用户指 run.command 的 open 导航，不是页面 JS）；且未征得同意就添加常驻机制。
- 怎么发现：用户当场叫停「我没有允许你这么操作，停止」。
- 修复：revert 全部轮询代码（934b583）；按原意改 run.command 的 open 带秒级时间戳强制真实导航（1a02117）。
- 沉淀：跨项目 MEMORY.md 协作偏好两条——常驻机制（轮询/自动刷新/守护）须先征得明确同意；需求动作先确认载体在哪一层（启动脚本 / 页面 JS / 服务端）。

### 2026-10-20（持续性）· BSD grep BRE `\|` 交替反复踩坑（当日 8+ 次）
- 现象：`grep "a\|b"` 静默返回 0 结果，连续误判「函数不存在 / 内容缺失 / 接口无定义」。
- 根因：macOS 自带 BSD grep 的 BRE 不支持 `\|` 交替；肌肉记忆反复覆盖已知教训（当日记录三次仍复发，含一次据此差点得出错误排查结论）。
- 怎么发现：查询结果为 0 与已知事实矛盾时，回头复查工具本身。
- 修复：所有受影响查询用 `grep -E` 重跑纠正结论。
- 沉淀：**硬规则升级——本项目一切多模式 grep 必须写 `-E`，禁止 `\|`**（从 memory 备忘升级为本 skill 案例级纪律）。
