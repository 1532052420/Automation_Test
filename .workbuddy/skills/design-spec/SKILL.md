# 自动化测试平台 · 项目 UI 设计规范

> 配套：设计方法论用 `oil-ui` skill（方向探索 / 截图对比 / 评审协议）；
> 图标一律走 `icon-generator`（24×24 SVG 单源）。本文件是**项目落地红线**，冲突时以本文件为准。

## 0. 设计变量唯一来源

- 所有颜色/圆角/阴影从 CSS 变量取，**禁止硬编码色值**（画布内的示意 HTML 除外）：
  - 平台：`web_platform/static/style.css`（`--sky`/`--dark`/`--line`…，日间定义 + `html.night` 块覆盖）
  - 定位器：`element_locator/static/style.css`（同约定）
- 近黑色双值陷阱：`--dark` 日间 `#1d1d1f` / 夜间 `#0b0b0c` 肉眼无差——**依赖"深底"的控件必须显式做日/夜两套**，不得只依赖该变量变色。

## 1. 日/夜双模式（强制）

- 任何新增面板/侧栏/浮层，**默认日间（浅底深字）与 `html.night`（深底浅字）两套必须同时实现**：
  用 `html:not(.night)` 前缀写日间覆盖（特异性压过旧的深色规则），夜间沿用 `html.night` 块。
- **文字对比度必须实测断言**（getComputedStyle 读色值或截图人审），"看不见的数字"= 事故。
- 表单控件、徽章、计时器、空态文案等小元素一并适配；`rgba(255,255,255,x)` 底 + `#fff` 字的白-on-白组合禁止出现在日间。

## 2. 布局与控件

- 表单数字输入框紧凑化：`max-width: 88px`，同组参数并排（参照「录屏配置」行）。
- 菜单/侧栏顺序变更、面板增删：同步检查 `data-panel` 切换逻辑与移动端（≤900px）折行。
- 浮动元素（悬浮球等）必须：跟随屏幕尺寸可见——拖拽位置记忆存取时**钳制进视口**，
  监听 `window.resize` 重新钳制；≤640px 提供紧凑形态。
- 新交互控件的**真实输入习惯**要纳入测试：用户会输「5-5」这类区间、会贴错单位——
  校验文案必须说人话（如「需为 0~5 的数字」），禁止把内部键名直接抛给用户（如 `fail_record_seconds: 值 '5-5' 不是合法整数`）。

## 3. 文案

- 界面文案说人话：不出现内部键名、变量名、术语黑话（反例：「未被用例实例化，保存时自动挂接（self.pageN）」）。
- 按钮文案 = 用户点击后的结果（「保存」「启动」），不是概念（「三件套一次完成」要解释清楚）。
- 空态必须有引导文案：告诉用户下一步做什么（反例：一片空白）。

## 4. 改动后自检（每次 UI 任务收尾逐条执行）

1. 日/夜两模式各截图一次，文字全部可读；
2. 受影响控件真实点击一遍（含取消/关闭/边界输入）；
3. 小屏（≤640px）与常规宽度各看一次，浮动元素可见；
4. 文案无黑话、无内部键名；
5. 与相邻既有控件的尺寸/间距不违和。

## 5. 评审升级

视觉方向拿不准、或改完仍被说丑：按 `oil-ui` 的评审协议走——
先出 2~3 个方向让用户选（如「收起按钮 10 款选样」），选定后再实现；不要自行猜审美。
