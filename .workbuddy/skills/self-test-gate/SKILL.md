# 自测质量门禁（Self-Test Gate）

> 来源：2026-09-30 视觉断言调试弹窗连环事故复盘。当天连续发生四类低级错误——
> 删码误切全站函数、控件事件从未绑定、守卫跳过既有绑定、验证只测自己写的路径——
> 每一类都可以被一道简单的门禁拦住，但当时没有任何门禁存在。
> 本 skill 的存在意义：**让"我以为改好了"变成"我验证过能用"**。

## 触发条件（满足任一即必须执行）

1. 任何代码修改任务（新增/删除/重构/修复）完成编码后
2. 用户使用质疑语气询问质量（"测过吗""为什么又坏""能不能做好"）
3. 交付前自查发现任意一项门禁失败

## 四道门禁（依次执行，全部通过才可交付）

### 门禁一：语法门禁
- 所有改动的 JS 文件：`node --check <file>`
- 所有改动的 Python 文件：`python -c "import <module>"` 或 `py_compile`
- 任一失败 → 修复后重新走门禁一

### 门禁二：引用完整门禁（删码/重构必做）
- 用 `git diff` 列出**被删除的全部函数/变量**
- 对每个被删符号 grep 全仓引用；有引用未清 → 补删或恢复函数
- **禁止用字符串切片/正则定位删除整个代码块**——必须以完整函数为单位删除，或删除后立即跑门禁二
- 高频公共函数（`esc` / `$` / `showToast` / `renderTopNav` 等）被删视为事故级，必须恢复

### 门禁三：行为自测门禁（浏览器实测，不可用单测替代）
- 在真实浏览器中打开受影响页面
- **逐个点击**本次新增/修改的每个可交互控件（按钮/下拉/输入），确认视觉反馈与数据流
- **取消/关闭类按钮必须单独点击验证**——它们是最常被遗漏绑定的控件
- 同一弹窗**二次打开**再点一次（防守卫/一次性绑定类 bug）
- 验证数据**回显**：打开→修改→保存→重新打开，确认数据不丢
- 夜间模式（或对照主题）切换一次，确认可读性

### 门禁四：数据链门禁
- 前端下发的每个字段名，在后端找到对应消费点（键名逐一核对）
- 真实保存链路至少完整走通一次（含写文件/落库），保存后重新读取核对
- 前后端字段命名不一致 = 事故级，必须修复

## 交付前自检清单（输出格式，缺一不可）

任务收尾时必须输出以下格式的自检清单，**逐项罗列实际执行的事项**，全部 ✓ 后才允许声明「以上自测门禁已全部执行」：

```
【自测门禁执行清单】
✓ 门禁一语法：node --check index.js / app_testing.js 通过
✓ 门禁二引用：git diff 比对，被删函数 X/Y 无残留引用
✓ 门禁三行为：浏览器实测「取消」「调试」「上传」逐个点击，取消关闭弹窗 ✓
✓ 门禁四数据：v 键→type 键归一化修复；保存后重新读取核对一致
```

**任何一项无法打 ✓**：如实写明「✗ 未通过 + 原因 + 后续动作」，并明确告知用户「自测门禁未全部通过」，**不得使用模糊表述蒙混**。

## 历史事故对照（本 skill 的每条规则对应的真实事故）

| 规则 | 当天事故 |
|---|---|
| 门禁二禁止切片删码 | renderTopNav 等 8 个函数被 index 切片误删，全页按钮失效 |
| 门禁三取消必点 | 调试弹窗取消按钮从未绑定，点击无反应 |
| 门禁三二次打开 | dataset 守卫使二次打开跳过全部绑定 |
| 门禁四字段核对 | 前端 v 键 / 后端 type 键，组合断言保存全丢 |
