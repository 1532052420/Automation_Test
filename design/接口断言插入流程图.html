UI 用例中插入接口断言 · 流程图 v2（修订版）

以现平台为基础；绿=新增 灰=现有 蓝=复用改造。场景：写歌 5 分钟后断言产出的视频/音频。
v2 修订（开发者/产品视角复盘，替代 v1）： ① 录入入口从「元素定位器」改为「用例编排」——接口步骤无元素，不该进元素向导；用户心智也是“在用例的第 N 步插入”，与用例编排的步骤编辑器天然匹配； ② 环境配置（接口地址/token）第一天起就集中到接口测试模块现成的环境变量体系（config/api_testing/environments.yaml，{{base_url}}/{{token}} 替换），不把 URL 写死进生成代码； ③ 产品规则约束嵌入范围：UI 用例里的接口步骤只允许「异步状态轮询」与「产物内容校验」两类，业务接口校验仍归接口测试模块（保测试金字塔）。

在哪配（产品入口）
平台「APP自动化 → 用例编排」已按用例-步骤视角组织；新增步骤类型「接口断言」，在任意 UI 步骤之间点 ＋ 插入。定位器回归纯元素职责，本方案不动它。
用例编排步骤编辑器（现有）
用例 → 方法 → 步骤列表，增删/排序/插入位置已是现成交互

定位器（不参与）
接口步骤无元素，不再塞进元素向导；避免弹窗进一步膨胀

阶段 3 · 执行：两通道交替，互不干扰
UI 通道（Appium · 手机）
步骤1 点击写歌 → Appium
↓（接口轮询期间手机空闲，不阻塞）
步骤4 断言作品卡 → 等待+截图
接口通道（requests/ffprobe · 本机）
步骤2 GET /works/latest 轮询 → status=2
↓
步骤3 下载 video_url → 时长≥30s · 非静音 · 分辨率
产品规则（什么允许放进 UI 用例）：① 异步状态轮询——UI 无法高效表达的等待（写歌 5 分钟）；② 产物内容校验——UI 渲染不了的文件（视频/音频）。
不放进来的：业务接口逻辑校验（登录/计费/权限…）归接口测试模块——避免接口变更打红整批 UI 回归，保住测试金字塔。
失败留证（现有 conftest 证据链）
阶段 4 · 报告：UI / 接口分列，定位一眼分流
步骤1 点击「写歌按钮」UI ✓ 截图
步骤2 接口轮询 接口 ✓ 响应体留痕
步骤3 音视频校验 接口 ✓ ffprobe 明细（31.2s/有声）
步骤4 断言作品卡 UI ✓ 截图
失败分流：UI 步骤失败=界面回归（截图+录屏）；接口步骤失败=接口/环境问题（响应体+ffprobe 错误入 allure）——两类失败域在报告里天然分开。
