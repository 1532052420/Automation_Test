# AppUI 自动化测试平台 · 功能测试用例

> 覆盖平台全部功能点。执行方式见文末；`[自动]` 用例由 `web_platform/tests/test_platform_api.py`
> 自动执行（自带平台启停 fixture，端口 8099，不依赖真实设备）；`[手工·需设备]` 用例需连接
> 手机并启动 Appium 后人工或经平台页面执行。

## 一、功能点清单

| 模块 | 功能点 |
| --- | --- |
| P1 首页 `/` | 统计卡（总执行/通过/失败/成功率）、最近执行表（10 条）、清空全部记录、侧边栏、底部设备/Appium 状态灯、8s 自动刷新 |
| P2 执行页 `/run` | conf 下拉切换、设备状态卡、执行参数覆盖（udid/包名/Activity）、用例树（文件勾选联动方法）、全选/全不选、开始执行、执行区（进度条/实时日志/停止/查看详情） |
| P3 执行详情页 `/runs/<id>` | 任务概要、用例执行记录（步骤树/断言截图/错误信息）、执行日志、执行中自动轮询、打开报告、删除本记录、截图 lightbox |
| P4 测试报告页 `/report` | 执行记录分页列表（10/页）、报告生成状态、详情/打开报告/删除、清空全部 |
| P5 元素定位器 `/locator` | 302 跳转同源 `/locator/`（已并入平台，无独立端口） |
| A1 执行生命周期 | run_id 生成（日期_序号）、单任务互斥、前置校验（Appium→设备在线→App 已安装）、参数覆盖仅本次生效、pytest 子进程、进度统计、日志双通道、30 分钟看门狗、停止（SIGTERM→SIGKILL）、result.json 归档 |
| A2 历史与恢复 | 平台重启后从磁盘 result.json 恢复历史列表/详情/日志、删除单条、清空（运行中保护）、run_id 格式防穿越 |
| A3 报告 | allure generate、报告静态服务（端口探测/就绪等待/同 run 复用/重复清理） |
| A4 安全 | 附件路径防穿越、case_nodes 参数白名单、非法 run_id 拒绝 |

## 三、发现的问题与修复记录

> 2026-09-12 第二轮：代码审查模块增强（记录/分页/筛选/文件锚点），新增 TC-062~066，
> 接口测试扩至 28 条全绿；期间定位并修复「平台进程持有旧代码仍占 8080 端口」的环境问题（重启解决）。
>
> 2026-09-16：按需求**下线「代码审查」模块**，删除其全部功能与代码（`代码调试/` 自检器、
> `web_platform/debug_routes.py`、`/debug` 页面与前端脚本、侧边栏入口、TC-060~075）。
> 接口测试由 38 条收敛为 **31 条全绿**；`/debug` 与 `/api/debug/*` 均返回 404。

| # | 问题 | 定级 | 修复 |
| --- | --- | --- | --- |
| 1 | 每次执行在 `config/app_ui_tmp/` 遗留 2 个设备临时文件（pid 与 desired_capabilities），长期堆积脏数据 | 中 | 任务终态归档时清理本进程写入的临时文件 |
| 2 | 平台重启后，磁盘历史里 status=RUNNING 的中断任务永远显示「执行中」（幽灵任务） | 中 | 读取磁盘任务时将 RUNNING/PENDING 归一为 ERROR「平台重启，任务中断」 |
| 3 | `POST /api/run` 并发竞态：互斥检查与任务注册之间有数秒校验窗口，并发请求可能产生双任务 | 中 | 启动主体加启动锁串行化 |
| 4 | 报告静态服务进程在平台退出后残留（孤儿进程占端口） | 低 | atexit 注册清理全部报告服务 |
| 5 | `POST /api/run` 的 case_nodes 未校验，API 直调可注入任意 pytest 命令行参数（如 `--help`、`-k`） | 中 | 节点白名单校验：拒绝 `-` 开头与非法字符 |
| 6 | `run.sh` 的 `web)` 分支调用仓库中不存在的 `run_web_ui_test.py`（历史死分支，误触发报 file not found） | 低 | 移除死分支并更新 usage |
