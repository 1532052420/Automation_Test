五个工具各自是什么、适合谁

scrcpy GitHub ↗

适合谁：追求极致性能与稳定、习惯命令行的人。所有 scrcpy 系工具的内核，行业事实标准。

  • USB 投屏延迟业内最低，1080p 高帧率，性能开销极小
  • 录屏 / 音频转发 / 摄像头镜像 / OTG / 熄屏投屏全都有
  • 无图形界面——所有操作靠命令行参数
  • 没有内置截图键，需自己配 adb screencap 命令

escrcpy GitHub ↗

适合谁：想要 scrcpy 全部性能又要图形界面、还想尝鲜 AI 自动化的人。综合体验最均衡。

  • scrcpy 图形化封装：内置窗口镜像 + 控制栏（旋转/截图/App/文件/终端）
  • 键盘映射可视化配置、多设备同步控制、批量截图/装 APK
  • Copilot AI 助手（MCP 协议）+ 可视化自动化编排（图像识别）
  • 无线连接局域网自动发现、中文界面、今天还在提交
注意：部分高级功能（EscrcpyX 扩展）为付费项，基础功能免费。

QtScrcpy GitHub ↗

适合谁：游戏多开、群控、自定义按键映射的玩家。老牌 Qt 实现，中文界面。

  • USB/网络 镜像+控制，免 root，内置截图/录屏按钮
  • 群控：一台电脑同时控制多台手机；自定义按键映射玩手游
  • 自定义 IP 连接、无线、剪贴板、APK 安装
注意：作者主力已转向商业版 QuickMirror（免费版限制 ≤10 屏）；更新频率略降。

ya-webadb (Tango) GitHub ↗

适合谁：不想在电脑装任何软件、手边有 Chrome 的人。打开网页插线即用。

  • 纯浏览器 ADB 实现（WebUSB）：无需安装、无后台进程
  • 实时镜像 + 控制 + 截图 + 录屏 + 文件管理器 + 终端
  • 同时是开源 TypeScript 库（npm），可集成进自己的网页/平台
注意：仅 Chromium 系浏览器；无线连接受浏览器限制，主要走 USB。

DeviceFarmer/stf GitHub ↗

适合谁：团队/测试实验室——多人在网页上共享一排真机。设备农场平台，不是单人工具。

  • 浏览器实时画面 + 远程控制任意接入设备，多点触控
  • 多用户账号体系：设备预约/占用/释放，REST API 管理设备
  • 截图、录屏、APK 拖装、文件管理器、远程 adb、反向端口转发
  • 与本平台思路最像：改造成"网页上看真机 + 自动化"的基础最好
注意：需要部署服务端（Docker 较方便）；音频转发不支持。

Sonic 云真机平台 GitHub ↗

适合谁：想要国产、界面现代、开箱即用的团队云真机平台。与 stf 定位相同，但中文生态与自动化能力更强。

  • 浏览器实时画面 + 远程控制，截图/录屏，文件管理
  • 内置自动化（可跑 Appium / uiautomator2 / Sonic 脚本）+ 文字识别
  • 多用户/团队/设备分组管理，插件生态（Jenkins 等）
  • 中文界面与中文社区（曾经的国产明星项目）
注意：2025 年 3 月起仓库已归档、停止维护——安全更新与新机型适配不再有保障，生产环境慎选。

一句话选型

单人调试追求性能 → scrcpy（能接受命令行）或 escrcpy（要界面）；
游戏/多开群控 → QtScrcpy；零安装、临时救急 → ya-webadb；
团队共享多台真机、多人远程用 → stf（持续维护）或 Sonic（界面现代、国产中文生态，但已停止维护，需自行承担安全与适配风险）。
结合本平台（自动化测试平台）：若想把"实时画面 + 远程控制"集成进来，stf 的多用户设备管理模型最贴近，scrcpy 协议的性能最好，ya-webadb 的浏览器方案部署成本最低。
