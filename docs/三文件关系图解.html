三个文件，一条链 —— 用例 / 页面 / 元素，一次说清

针对的问题：「弹窗里有四个下拉，是不是四个文件？」—— 不是。是 3 个文件 + 1 个起错名字的方法下拉。下面全部用仓库里真实存在的代码说明。

3 个文件
用例 / 页面 / 元素（三件套）
方法不是文件
方法是文件里的一段代码
绑定靠 import
引用哪个就是哪个，不看名字

1先记住这一屏

📄 文件一：用例文件test_user_search_01.py
装的是「场景剧本」：先点什么、再输什么、最后断言什么。每一步是一行调用。
📄 文件二：页面操作文件User_search_01Page.py
装的是「每台电器的说明书」：这个屏幕上每个可做的动作，一个动作一个方法。它就是弹窗里「写入页面文件」选的那个文件。
📄 文件三：元素文件user_search_01Elements.py
装的是「按钮在哪」：每个元素的定位方式 + 定位值。全库共享，同定位自动复用。
你数的第四个「操作方法 / 页面操作」—— 不是文件，是文件里的一段代码。就像「周三」是日程本里的一页，没有人会为周三单独装订一个本子。弹窗里那个叫「页面操作」的下拉，选的其实是用例文件里的某个 test 方法——它名字起错了，后续版本会改名「用例方法」。

2一条调用链看懂三个文件怎么咬合

以真实存在的用例「搜索歌曲」为例：你在弹窗录「点击搜索按钮」并保存后，磁盘上是这样的——

📄 用例文件 test_user_search_01.py
多了一行调用（剧本上的一句台词）：
page.click_btnSearch()
→
📄 页面操作文件 User_search_01Page.py
多了一个方法（说明书上的一页）：
def click_btnSearch(self):
  appOperator.click(
    self._elements.btnSearch)
→
📄 元素文件 user_search_01Elements.py
元素定义（标签册上的位置，早已存在，不新增）：
btnSearch = CreateElement.create(
  ID, 'com.x:id/btnSearch')

保存一步 = 用例文件加一行 + 页面文件加一个方法 + 元素文件确认定义存在。三个文件，从头到尾没有第四个文件出现过。

3三个文件的真实长相（仓库原文，可对照打开）

彩色行 = 咬合点：蓝色是被用例调用的方法名，绿色是页面引用元素的位置，橙色是元素定义。

📄 文件一 · 用例文件 cases/.../test_user_search_01.py
# 用例中文名：用户搜索-精确昵称
from ... import APP_UI_Android_demoProject_Client
from pages.User_search_01Page import User_search_01Page   ← 绑定页面②

class TestUserSearch01:

    def setup_class(self):
        self.appOperator = Client(...).appOperator
        self.page = User_search_01Page(self.appOperator)   ← 实例化：引用哪个就是哪个

    def test_user_search_01(self):   ← 弹窗「页面操作」下拉选的就是它，它不是文件
        page = self.page
        page.click_btnSearch()            ← 去页面文件找同名方法
        page.input_search_input('所谓伊人')
        page.click_search_submit()
        page.assert_user_nick_text('所谓伊人')
弹窗「目标用例文件」下拉选的就是这个文件；「页面操作」（将改名「用例方法」）下拉选的是文件里的 test 方法。
📄 文件二 · 页面操作文件 pages/User_search_01Page.py
# 页面对象（用例包：user_search_01）
from elements.user_search_01Elements import User_search_01Elements   ← 绑定元素③

class User_search_01Page:

    def __init__(self, appOperator):
        self.appOperator = appOperator
        self._elements = User_search_01Elements()   ← 装上元素：引用哪个就是哪个

    def click_btnSearch(self):        ← 用例那行调用的就是它
        self.appOperator.click(
            self._elements.btnSearch)   ← 去元素文件找 btnSearch

    def input_search_input(self, text):
        self.appOperator.sendText(
            self._elements.search_input, text)
弹窗「写入页面文件」下拉选的就是这个文件；录一步=往里加一个方法，同名覆盖、新步骤新增。

4执行时的一次点击，五步走完

1
pytest 跑到 test_user_search_01，先执行 setup_class
看到 self.page = User_search_01Page(...) → 页面定了，就是它，不可能换成别人
2
执行 page.click_btnSearch()
page = self.page → 到 User_search_01Page.py 里找同名方法
3
方法体执行 appOperator.click(self._elements.btnSearch)
self._elements 在 __init__ 里装配好了 = User_search_01Elements 的实例 → 元素文件定了
4
取 btnSearch 的定义 → 拿到定位值 ID: com.x:id/btnSearch
5
appium 在真机上找到这个按钮并点击，截图存证 ✅

5弹窗里四个下拉的真相（你觉得是四个文件的地方）

弹窗里的下拉展开后选项长什么样选的是是文件吗
写入元素文件（元素栏）aaaaElements.py、opcheckElements.py…… 都以 .py 结尾元素文件✅ 是（文件三）
目标用例文件（用例栏）test_aaaa.py、test_user_search_01.py…… 都以 .py 结尾用例文件✅ 是（文件一）
写入页面文件（操作栏）AaaaPage.py、User_search_01Page.py…… 都以 .py 结尾页面操作文件✅ 是（文件二）
页面操作（用例栏，旧名）test_user_search_01、test_e2ecase…… 没有 .py，是方法名用例文件里的 test 方法（写到哪个方法的末尾）❌ 不是——是文件里的位置

自己验证：展开四个下拉对比选项——三个文件的选项都带 .py，唯独「页面操作」不带。它马上会改名「用例方法」，改完弹窗自己就把 3 个文件说清楚了。

6不信的话，做个实验

打开 cases/app_ui/android/demoProject/、page_objects/.../pages/、page_objects/.../elements/ 三个文件夹，数一数文件个数。然后随便录 10 步、保存 10 次，再数一遍——

文件个数一个没变，只有 3 个文件各自变厚了。
如果「操作方法」是文件，录 50 步就该冒出 50 个新文件——它从来没有出现过。这就是「方法住在文件里」的实证。

7黑话 → 人话 对照表（终极防绕指南）

听到/看到的词它到底是什么在哪
用例文件 / 三件套之一场景剧本，一行一步cases/app_ui/.../test_xxx.py
页面操作文件 / Page 文件 / 页面文件同一个东西：某块屏幕所有动作的说明书page_objects/.../pages/xxxPage.py
元素文件 / 元素库文件按钮地址簿：定位方式 + 定位值page_objects/.../elements/xxxElements.py
用例方法（弹窗旧名「页面操作」）用例文件里的一个 test 方法，不是文件用例文件内部
页面方法Page 文件里的一个方法，不是文件Page 文件内部
操作类型（点击/输入/滑动…）动作词汇表，全局通用，不占文件弹窗操作栏选项
