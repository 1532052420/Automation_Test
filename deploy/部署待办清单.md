## 二、你需要做的事（按顺序）

### 第 1 步：准备一台服务器

- 配置建议：2 核 4G 起步、磁盘 40G+（跑接口用例足够；跑 APP 用例另需接真机）
- 系统：**Ubuntu 20.04+ 或 Debian**（一键脚本按这个写的；如是 CentOS 请告诉我，我改脚本）
- 网络决定形态：
  - **内网服务器**（组员同一办公网/VPN 可达）→ 安全策略最简单，推荐
  - **公网服务器** → 必须启用 nginx 口令 + 强随机 ADMIN_TOKEN，防火墙只开 80/22

### 第 2 步：把下面【信息清单】填好发给我

### 第 3 步：等我执行部署（或你按 deploy/DEPLOY.md 自己执行，都是现成命令）

```bash
# 服务器上三条命令即可完成初始化：
git clone https://github.com/1532052420/AutomationTest-1.git /opt/AutomationTest
sudo bash /opt/AutomationTest/deploy/install_server.sh        # 加 --with-appium 则连 Appium 一起装
sudo bash /opt/AutomationTest/deploy/install_server.sh --with-appium   # 仅接真机跑 APP 用例时需要
```

### 第 4 步：验收

- 浏览器打开 `http://<服务器IP>/` → 测试平台（首页/执行/报告/代码审查/管理后台）
- `http://<服务器IP>/locator/` → 元素定位器
- 用组员账号在管理后台上传一条用例 → 执行页能立刻看到 → 跑通接口用例

## 四、安全提醒（公网部署必读）

1. `ADMIN_TOKEN` 必须改成强随机值（这是管理后台上传/删除的口令）
2. nginx basic auth 建议启用（平台整体访问口令）
3. 云安全组只放行 80（网页入口）和 22（SSH）；**8080/4726 不要对公网开放**
4. 测试报告里的端口（4000 起随机）仅适合内网分享；公网场景建议后续改为统一走 nginx

## 五、已知限制（部署后组员会遇到的）

- 执行平台同一时刻只允许 1 个执行任务，第二个人点开始会提示等待（先到先得）
- 元素定位器同时适合 1 人抓元素
- 服务器没插真机时：执行页跑 APP 用例、定位器抓元素不可用；接口用例、代码审查、管理后台、报告全部正常
- 管理后台上传的文件保存在服务器本地；如果同时用 git 管理，记得定期把服务器上的新增文件提交回仓库

## 六、常见问题

- **改了框架代码怎么生效？** 服务器上 `git pull` 后 `sudo systemctl restart automation-platform`（新增/删除用例和元素文件不用重启，平台自动识别；改了方法签名需要重启）
- **服务挂了？** `systemctl status automation-platform element-locator` 看状态，systemd 会自动拉起
- **怎么回退版本？** `cd /opt/AutomationTest && git checkout backup/pre-refactor-20260911` 后重启服务
